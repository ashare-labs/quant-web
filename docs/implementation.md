## 明确缺口

- 旧单文件接口只存 Python 源码，不提供文件重命名/删除；项目接口支持整体改名移动及内部文件编辑。两种模式均不存日期/资金/频率，不提供完整策略项目删除或通用版本系统。目录响应没有修改时间，列表相应显示“—”，不借用浏览器时间冒充文件时间。
- paper 创建/推进/暂停/恢复已退役，页面不把本地记录冒充运行中的模拟交易。
- 指数历史成分池、稿件里的组合回测/交易过滤/预计算全目录 IC 排名无对应接口。不复制稿件的历史账户数据；列表 IC/IR 不伪造，所选真实任务的统计评价可读。
- 任意 Python 内存不能断点续跑；无假恢复按钮。状态优先使用 display_status；retired/runtime_unavailable 不展示为等待运行。
- 普通结果使用当前可见表 CSV；原服务响应只在“诊断 JSON”导出，不另造普通 JSON 格式。基准收益、Alpha、Beta、Sharpe 未提供时为“—”，不能记零。

## 实现边界

各页采用同一 React/TypeScript 入口和共用样式，产物为七个独立 HTML 入口及静态资源。不保留旧演练平台页面、七策略注册和旧 portfolio/daily API。后端实现不在本仓修改范围。

策略文件列表保留“全部文件”目录提示与五列表格；文件夹使用同一张表，进入目录后可通过“全部文件”返回。目录从服务读取；旧浏览器文件夹及尚未落盘的草稿仍可访问，不按名称猜测合并或删除记录。服务明确解析出的文件别名按下述 F6 规则保留原草稿和规范身份。旧草稿名称后注明“浏览器草稿”。文件行的“历史回测”列提供该策略的回测列表入口，不另加全局历史分类。没有编译运行契约时仍显示“—”。独立结果页及查看源码入口继续使用通用任务详情、结果、日志和 manifest 读取。

## 策略所属回测列表

旧单文件 `strategy_id` 的身份模型为 `saved_relative_path`：完整相对路径代表保存的策略位置；不同目录的同名文件互不合并；同一位置编辑源码后的运行仍在同一列表；改名后保存会创建新的文件位置，原文件和原记录保留。已保存文件的新请求显式绑定该身份，尚未保存的纯浏览器草稿仍可提交但保持未归属。请求的策略身份不会为了列表归属而被客户端猜配或改写。

列表只发显式 `strategy_id` 的 `/python/backtests` 请求，不调用省略身份的未关联列表，不自行从 name、source、hash 或 localStorage 推测归属。响应及每行身份必须与选中策略相同；跨页加载直到 total，数量变化、缺页、重复 ID 或混入其他策略均报错，不呈现为完整成功。全部结果载入后按创建时间倒序显示、在当前策略内搜索，每页20条。当前运行中的任务每5秒重新读取；失败和无结果记录仍可进入单次详情。

## 文件保存语义

服务端文件以相对路径寻址，编辑器使用 `?file=`；旧 `?draft=` 仍可打开浏览器草稿，`?job=` 继续只读查看冻结源码。每次打开关联文件仍 GET 核对文件。存在 `workingCopy=true` 的当前编辑时，恢复整条 Draft 的源码、名称和配置并明确标记未保存；没有当前编辑的旧记录继续从文件读取源码并恢复既存参数。普通读取不回写存储；明确的别名响应按 F6 规则原子保留。读取失败会报错并禁用保存/运行，已有工作内容仍可见和导出，不把它声称为服务端最新文件。

每次编辑都将源码和配置保留到同一条现有 Draft，允许暂缺日期、金额和未完成源码。提交前再次确认这份编辑已保留；本地存储失败则留在页面、报错、阻止新提交并保留离页提醒，避免接受后丢失内容。提交成功或失败都不清除当前编辑。历史 manifest 是冻结运行证据，不用于恢复可编辑内容。新提交的纯浏览器草稿结果保留 `?draft=` 返回入口，仍不声明文件归属。

新建策略立即 PUT 空 `.py`，`overwrite=false`，同名错误在现有弹窗反馈区显示，不自动覆盖或改名。打开已有文件后保存传 `overwrite=true`；名称改变时以新路径创建，原文件保留，不调用不存在的重命名或删除接口。新建文件夹接 POST，支持在当前目录继续创建子目录；目录导航和刷新使用 GET。

只有 PUT 成功后才将当前 Draft 标记为已保存；保存期间暂时禁用编辑和重复保存。另存为时，在一次 localStorage 写入中更新原文件和新文件的记录，避免新名称/源码留在原文件的工作副本。已确认未保存的失败保留编辑内容；网络中断、响应异常或 `STRATEGY_SAVE_UNCERTAIN` 会重新 GET 核对，哪怕读回一致也不冒充刷盘已确认。用户可再次主动保存；不自动重试写入。源码成功但浏览器配置保存失败时明确区分两者并保留离页提醒。保存不会执行代码、提交回测、修改冻结结果或隐式生成配置旁车文件。

已用该契约对应后端的隔离部署验证目录、新建/覆盖、重新读取、服务重启后的内容保留；浏览器还验证同名拒绝、写入失败、不确定响应读回、配置存储失败、旧草稿和布局保持。真实部署与 41846 未切换，后续需父任务统一联验。

## 运行频率

编辑器按原设计在初始资金之后、Python3 标记之前恢复原生选择框，选项顺序和文案为“分钟”“日”，对应 `1m`、`1d`。原稿默认选中首项分钟；新建及没有频率字段的旧草稿因此采用可见的 `1m` 默认，已存选择不覆盖，不根据源码或文件名猜测运行模式。控件采用原稿的 66 × 44 尺寸和共享边框/字体样式，保留既有日期/资金标签及响应式换行；未重新设计工具栏。

频率写入现有浏览器 `Draft.frequency`，和当前源码、日期、资金一起随编辑保留；唯一“保存”入口负责将 Python 文件写入服务。打开旧草稿不会自动回写；正常保存时写入显式值，保存失败保留本次选择和原存储记录。历史只读页使用 manifest.request.frequency，缺失则显示“未记录”，不套用新建默认值。

提交适配应使用 `src/shared/drafts.ts` 的 `pythonBacktestConfig(draft)`：验证完整日期、资金和频率，返回类型化 `{start_date, end_date, initial_cash, frequency}`。`frequency` 永远明确为 `1m` 或 `1d`，不能省略后依赖服务端默认；`initial_cash` 是正确数值。`validateConfig` 仍返回数值资金，保持已有调用兼容。

频率控件验证涵盖切换、保存重读、旧草稿缺省/既存值、失败保存及历史只读。下述联合验证进一步检查真实 POST、原生执行和结果中的频率；源码注释不会覆盖界面选择。
