# quant-web · 本地量化研究工作台

## 项目简介

quant-web 是 AQ 的本地浏览器界面，用于编辑策略、运行组合及日频回测、查看任务结果、连续模拟账户和已保存行情。金额、持仓、成交及审阅结论均来自后端；前端不重算账本。

## 安装指南

需要 Node.js 22.18 或更新版本。在源码根目录执行：

```sh
npm ci
npm run check
npm run build
```

后端使用配对的 AQ/AD 候选，数据与账户由其本地命令准备。[配置说明](docs/configuration.md)列出了服务地址与端口。

## 启动方式

先准备 AQ 通用服务和需要的 paper 服务，再启动前端：

```sh
npm run doctor
npm run dev
```

打开 `http://127.0.0.1:41839`。默认进入正式数据选择页；前端命令不会启动后端或 worker。统一部署清单可提供端口和后端环境变量。检查生产构建可使用 `npm run preview`，它与开发服务使用相同的代理配置和端口。

## 使用指南

| 页面 | 用途 |
|---|---|
| `#/data` | 搜索主库证券与日期，核对参考来源及普通回测覆盖，发布到组合回测；独立价格诊断需明确选择 |
| `#/portfolio` | 编辑及注册策略、预检查、创建多证券组合任务、查看逐日账户与成交 |
| `#/tasks/daily` | 独立固定日频评测：绑定评测数据、选择参数，创建、取消与恢复任务 |
| `#/tasks/paper` | 核对模拟账户的逐日快照、成交、持仓和来源限制 |
| `#/paper` | 查看冻结会话、接收数据、推进交易日、暂停和恢复 |
| `#/market` | 已发布研究与固定样本行情：按存储别名、dataset ID 和实际证券读取快照与覆盖 |
| `#/execution/runs` | 使用人工场景检查原生执行和运行回执 |

创建请求会先保存原参数与幂等键。响应中断时，先核对任务状态，再重试保存的同一请求。缺失结果保持“未提供”，不会补成零或拼接历史样例。

## 限制与说明

这是本地研究界面，尚未部署。新版源码及契约需要独立联验，不继承旧版本验收。接口匹配、任务完成、原生对账通过和人工审阅是不同结论；以当前响应中的身份、范围和状态为准。

正式主库入口没有两股固定样本限制，默认普通回测按当前窗口检查真实价格、状态和公司行动来源。来源覆盖仍受日期、税费模型与历史可见性声明约束；未覆盖的证券或日期会明确拒绝，不会补数据或自动改为诊断。独立价格诊断需主动选择并确认限制，非经济总收益；含公司行动日程的数据不能剥离转换。模拟账户不授予实盘权限。历史封存结果接口已退出新版产品，原证据与账户保持原样。

`npm run package` 生成经过内容检查的静态包，位于忽略的 `.local/packages`。历史 `output`、数据库、个人配置和过程材料不进入当前发布树。
